# ADR 0001. Хранитель живёт вне сервера: пинг + ИИ-агент в GitHub Actions/на Mac, ключ с белым списком

Статус: принято 2026-10-19 (слово владельца через «🎛 Оркестратор»: «согласен со всеми рекомендациями пула»).

## Контекст
2026-10-19 владелец остался без Инбокса: nginx отдавал 502 в 17:43–17:45 и 19:54. Инбокс за день перезапускали
11 раз (деплои соседних сессий), swap был забит полностью (4095/4095 МБ). Снаружи этого никто не замечал:
наблюдаемость и алерты живут **на том же dede** и ложатся вместе с ним. Машина obs из poh-observability#19
не заказана. Предыдущая сессия (poh-observability#17) отклонила kagent: нужен Kubernetes, ≥ 5 ГБ памяти,
линия 1.x — альфа.

Ограничения:
- Claude нельзя запускать на серверах в РФ (правило 1 CLAUDE.md): ни на dede, ни на Selectel-VPS.
- fail2ban на dede в режиме **aggressive**: 3 события за 10 мин → бан IP на 24 ч, и считаются даже
  пустые подключения к 2222 (`kex_exchange_identification`, `Connection closed … [preauth]`).
  Пинг с Mac владельца по порту SSH забанил бы самого владельца.
- Бесплатный тариф GitHub-организации: 2000 минут Actions в месяц, из них ~1400 уже уходит на другие репо.

## Решение
Три слоя, все вне dede, кроме оболочки:

1. **Пинг снаружи** (`probe/probe.py`, только HTTPS, 7 адресов, упавшее перепроверяется через 15–30 с):
   - сторож на Mac (launchd, раз в 2 мин, пока Mac не спит; сначала проверяет свою сеть);
   - запасной cron в GitHub Actions раз в 3 часа (~240 мин/мес) и «хранитель на посту» по понедельникам.
2. **ИИ-агент** (`agent/heal.sh`): Claude Code CLI (`claude -p`) с единственным инструментом
   `./agent/g` — SSH с ключом `heal`. Работает в GitHub Actions (токен подписки владельца —
   `claude setup-token`) или на Mac (если Actions недоступен или не настроен). Telegram-бот: 🚨 → доклад → ✅/❌.
3. **Оболочка на сервере** (`server/guardian-shell`, forced command в `authorized_keys` aleks):
   - ключ `heal`: диагностика и обратимые действия из белого списка — рестарт 33 юнитов (не больше 3 в час
     на юнит; hermes-gateway и системные не входят), снятие тестовых браузеров и прогонов старше 10 минут,
     перезапуск Chrome в контейнере;
   - ключ `approved`: любая команда под aleks без sudo и без секретов. В Actions этот ключ лежит в
     секрете и пишется на диск только после ✅ владельца, а у агента его нет в окружении.

Профилактика: `poh-restart` (рестарт со следом в `changes.jsonl`, который читает агент) и earlyoom
(шаг с sudo — для владельца).

## Последствия
- `+` Сбой виден снаружи: с Mac за ~4–6 мин, без Mac — за ≤ 3 ч (cron). Агент чинит типовые причины сам.
- `+` Серверу ничего не добавляется, кроме ~400 строк Python и двух строк в `authorized_keys`.
- `−` Если Mac спит, реакция медленная (cron раз в 3 ч). Быстрее — внешний пингер (Healthchecks/UptimeRobot
  → `workflow_dispatch`) или obs-VPS с Gatus. Это следующий шаг.
- `−` Ключи лежат в секретах GitHub. Кража `approved` = доступ под aleks, как и у ключа `harness-mts` на Mac.
  Белый список защищает от ошибок агента, а не от кражи ключа.
- `−` Если не отвечает SSH (нагрузка 140, как 2026-10-07), агент только докладывает. Перезагрузка — в панели
  Selectel (сервер в Selectel по whois). API Selectel с токеном владельца — следующий шаг.
- `−` Sudo-правило `server/install-sudoers.sh` (`fail2ban-client status sshd`, `set sshd unbanip *`) получают все
  процессы под aleks, в том числе агенты Hermes: они смогут снять бан с любого IP. Защиту от подбора это
  ослабляет мало: банить они не могут, а вход только по ключу. Взамен главная «недоступность» (бан IP
  владельца) снимается без пароля и мобильного интернета.
- Минуты Actions: ~240 в месяц на пинг плюс ~5 на каждый разбор. При перерасходе бесплатного лимита
  Actions встанут, поэтому сторож на Mac — основной, а не запасной.
